# SentinelX — Alert Management

## 1. Alert Lifecycle

Every detection generated by the detection rules engine is stored in the `alerts` table with an explainable risk score.

### Alert Status Transitions:
- `new` -> `acknowledged` -> `investigating` -> `resolved`

---

## 2. Alert API Endpoints

### List Alerts:
`GET /api/alerts`
Returns alerts joined with source normalized log details, MITRE ATT&CK technique IDs, and threat intelligence counts.

### Update Alert Status:
`PATCH /api/alerts/:id/status`
Payload:
```json
{
  "status": "acknowledged"
}
```

### Get Alert Enrichment:
`GET /api/alerts/:id/enrichment`
Returns:
- `alert`: Alert details
- `mitre_attack`: Array of mapped MITRE ATT&CK techniques
- `threat_intelligence`: Array of mapped threat IoCs
